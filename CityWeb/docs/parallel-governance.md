# CityWeb 并行开发治理架构 v1（总管制）

> 溯源：CEO 令 2026-11-26「你也要做好这些并行开发的准备，底层架构啊之类的，不要让它们互相冲突。然后耦合的时候要有一个总管」。
> 本文件=CityWeb 一切并行泳道的宪法。冲突时本律优先于任何单泳道进度。

## 一、三层架构（总管-泳道-模块）

```
总管（指挥席会话·唯一）
  ├─ 泳道（N 条·隔离 git worktree·每条一个后台 agent）
  │     └─ 只产「新文件」，禁碰共享面
  └─ 模块注册表（registry.ts 唯一仲裁面）
```

**总管=唯一接线人**：main.ts / registry / tsconfig / vite.config / package.json / dist 构建产物——这六件**永远归总管独占**。泳道 agent 碰任何一件=违规作废。这是零冲突的根：所有耦合点收敛到一个人手里。

## 二、泳道冲突域规范（防冲突三律）

1. **文件独占律**：泳道只准写派单点名的**新文件**路径。两泳道永不写同名文件；同目录共存合法（git checkout sha -- path 引入天然隔离）。
2. **契约冻结律**：泳道交付的 export 面必须与派单契约**逐字一致**（接口名/函数签名/update 参数序）。契约由总管在派单时定死并写入 `src/registry.ts`——接线时只看注册表，不看泳道内部实现。
3. **依赖单向律**：模块只准 import `three`/`../util`/`../palette`/`../types`/`../city/layout`（稳定底座）。模块互相 import=禁（防止泳道间耦合——需要别人数据时由总管在接线层传参）。

## 三、模块注册表（src/registry.ts）

总管维护的唯一模块清单：每模块一行 `{ id, file, build 函数名, rig 类型, update 签名, 泳道来源 sha, dc 预算 }`。
- 新泳道交付=总管在注册表加一行+接线 main.ts（一删一改即回滚）。
- 注册表即「耦合总账」：任何人看一个文件就知道全城有什么模块、谁产的、怎么接。
- 接口冲突在注册表层就能发现（两模块同名 build 函数=注册时拒绝）。

## 四、CI 闸（总管合并四门，任一红=打回泳道）

1. `npx tsc --noEmit` 零错（类型门）
2. `node tools/build-static.mjs` 产出（构建门）
3. `python qa/perf_probe.py`：JS 零错+perf HUD 出数（冒烟门）
4. offender 复测：`scene.traverse` 计数对照 registry 的 dc 预算（性能门——合批泳道专属）

## 五、泳道生命周期（总管 SOP 八步）

1. 建泳道 worktree（prechange）→ 2. 合最新 main 基线 → 3. 派单（契约+只读文件清单+新文件路径+四门+提交规范）→ 4. 等交付（sha+报告）→ 5. `git checkout sha -- 路径` 引入 → 6. 注册表加行+main.ts 接线 → 7. 过四门 → 8. commit+push+清 worktree（junction 先删）。

**超时/半成品处置**（今天泳道 C 实判例）：勘察型交付（常量捕获/方案论证）与实施分离续派——勘察产物直接写进续派 prompt，不浪费。

## 六、他窗会话协作（同仓多执行体）

- 他窗（如居民行为层）与总管窗共用主树：**总管推送前必 fetch 看他窗新 commit，冲突走真合并保双面**（今日三次实判例）。
- 主树脏面=他窗在飞：总管等其 commit 或 stash 隔离，禁硬闯。
- tick 快照类运行时再生文件与合并打架：stash push/drop 一次性隔离。

## 七、已在役的实证（本架构=今天实战沉淀）

- 三波 11 泳道零 git 冲突（文件独占律天然成立）。
- 唯二冲突均在**共享面**（main.ts 两窗同时改+snapshot 运行时件）→ 归因「接线权分散」，本架构把接线权收归总管根治。
- 合批泳道 dc 实测链：2944→2156→2048→1931→1560（registry 的 dc 预算列让性能账可审计）。
