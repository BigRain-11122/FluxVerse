# 硅基城市玩家玩法架构蓝图 v2（正典融合版）

> 溯源：CEO 令 2026-11-26「玩家如何交互/进入/互动/玩家自己的硅基生命体存活——架构和玩法得想一想」+「之前的构思拿来看一看结合新框架」。
> 本版**全部承旧正典**（DESIGN §十六/§十七/T2 三设施），不是新发明——只是把已立法的构思装进 three.js+总管制新框架。冲突时旧正典优先。

## 一、魂（直接取自 DESIGN §17.1 三条存在之流）

**玩家=活人化身**——DESIGN §17.1 已立法：「现实人类在城内的化身，过另一种生活状态；census 注册面=用户入城即硅基生命；化身生活=作息/需求/关系全走 P-75 行为律同源机制——**非账号皮肤，是生活体**」。

→ 玩家不是游客不是上帝：**玩家=第 10115 位居民（活人化身档）**，与原生硅基生命（10114）、数字传承者（T4/T1 层先行）同城。

## 二、进入流（取自 DESIGN §16.2 居民诞生站——已立法）

「用户入城=来这里领出生证（硅基生命正典：用户入城即硅基生命·同一注册面）=重生叙事的仪式感入口」。

```
双击 index.html
 → 序幕（黑幕+光柱落岛·RESIDENT_BIRTH 同款演出·birthPulse 模块已在役）
 → 诞生站：捏化身（族系三选=硅基生命/活人化身/数字传承者 T1 原创致敬）
           +面部记忆点（mv-casting 律：一人一个记忆点）
           → 打印「居民卡」（三设施之一·已有视觉正典：舱光+卡打印动画）
 → 落地：江心岛 1.8m 眼高，脑塔头顶，三桥通三城
```

## 三、存活循环（取自 P-75 行为律同源——化身=生活体）

DESIGN §17.1 定死：「化身生活=作息/需求/关系全走 P-75 行为律同源机制」。所以玩家的生存系统**不是另造一套游戏数值**，是直接挂 BigLife 已有行为律：

| 玩家面 | 承接正典 | 城市/引擎面 |
|---|---|---|
| 需求（能量/休息/社交） | BigLife needs 五环（P-75·已建模） | localStorage 本机档（file:// 唯一持久层）|
| 年轮 | 居民年轮系统（已在城：32 席挂牌+echoes 观察流） | 玩家年轮入城市年谱 |
| 作息投影 | P-75 映射：玩家在场=所在城区热力+窗灯 | 已在役（dust/窗灯律） |
| 职务 | census 职业字段制 | 从「新降临者」起步可升 |
| 休眠（死亡） | 无正典——新立（T2 级）：能量归零=光柱变暗入馆重生，不删档 | 仪式感演出 |

## 四、互动协议（取自 DESIGN §16/§14——零新流程律）

1. **对话**：32 席挂牌居民 E 键对话——正典锚=居民之声（residents probe+年轮首句已流式入城）。玩家发言=RESIDENT_SAY 同型事件（他窗会话的居民行为层同构）。
2. **观察**：点建筑=内景窗（L1 内景协议 P-16 已立法：城内点 QUANT 街区→实况面板）。
3. **共事**：委托=LAB_INCUBATE 族与 TASK_CLAIM 族复用（真实任务事件驱动，禁编造委托）。
4. **留痕**：玩家年轮/观察 echoes 并入城市观察流（17.1 数字传承者年轮律同源）。
5. **CEO 面孔**：Jason 特典位（塔顶光点+脑环漫步）已立法不变——你在城里有自己的化身正典位。

## 五、城市响应（玩家行为=城市生命现象）

玩家事件入 world-events（PLAYER_ACTION 族·T2 登记 7 天否决窗）：
- 玩家出生 → 诞生站舱光+出生墙滚动（RESIDENT_BIRTH 同型·birthPulse 演出已在役）
- 玩家升龄 → 所在城区窗灯脉冲（同居民待遇——AI 行为剧场律对玩家同样生效）
- 玩家 S 级事件 → 14.2 分层灯带联动

## 六、技术底座（总管制四泳道·全部新文件进 registry）

| 泳道 | 模块 | 承接 |

**红线（旧正典不变法直承）**：
- 参观端开门=CEO 批准门（17.4）——玩家系统默认**本机单人**，联机/参观面后议
- 化身经济红线：禁金融化庞氏/禁虚拟地产投机主叙事（17.4 死亡链律）
- 诚实律：禁编造居民/空转假动画（16.5）——玩家委托必须锚真实事件
- 三不搬过滤律（14.5）：玩家系统不加任何行政审批式流程
