## §1 基准谱：虚拟活动彩排/技术检验结构的行业语法（四段式架构+dry run 清单法+ROS 执行脚本三层）

| 源 | 定谳句 | 实数/标准 |
|---|---|---|
| 专业虚拟企业活动四段式彩排清单（DJ Will Gill·虚拟活动制作公司专业清单件·2026-07-06 发表·全文直取 38,973 字符）——架构层 | **四段式 T-minus 时间线 verbatim**：「**Tech rehearsal (T-7 to T-3 days before event), dry-run rehearsal (T-3 to T-1 days before event), dress rehearsal (T-1 day or event morning), and event-day pre-show checks (T-90 minutes to T-0)**」——每段各有目标/参与面/pass-fail 判据；**段落纪律 verbatim**：「Tech rehearsal tests whether the tech works. Dry run tests whether the content flows. Dress rehearsal tests whether everything works together under live conditions. Pre-show tests whether everything set up before is still functional」——「**Confusing the stages (using tech rehearsal to also test content, or trying to fix tech problems at dress rehearsal) produces worse outcomes than any single stage would produce alone**」；**跳段定谳 verbatim**：「Skipping any stage is a professional-quality compromise, not a cost saving」；2020 式彩排终结宣判：「In 2020 and 2021, 'rehearsal' often meant **a 20-minute Zoom call with the CEO to test their microphone the day before the town hall. That era is over**」 | **虚拟比线下更需要彩排四理**（技术面更大——每远程讲者各自跑摄像头/麦/网络/电脑/客户端=各自失败点；**失败不可当场救**——「A remote speaker whose home Wi-Fi drops five minutes into their segment **cannot be recovered by anyone at the venue**」vs 线下坏麦 90 秒换备用；协调开销更高——无人能拍肩交接；注意力曲线无情——线上摩擦=观众流失事件）；**技术检验基线五项**：10 Mbps 最低上下行 HD 流+硬线以太网优先 Wi-Fi+Intel Core i5+8GB RAM 计算基线+有线耳机优于无线+**每位关键参与者备份外设备妥**（backup peripherals staged for each critical participant）；**主彩排一周窗**：「plan to schedule any webinar practice run about one week before the live event」——太早=技术记忆不保·太近=无修复跑道；**contingency 彩排段=最被跳过的最有价值段**（显式演练失败模式：讲者掉线/平台崩溃/幻灯片卡死/音频劣化）+**预录备份 verbatim**：「having pre-recorded content **'in the can to air'** as backup, which requires prior rehearsal to deploy cleanly」；**彩排暴露临近问题的升级律**：小=修复+复测/中=备份准备（替补讲者/预录段/形式切换）/大=「honest planner-vendor conversation about **scope reduction or postponement** rather than pushing through a broken event」；**彩排=真实专业劳动**：「Vendors who quote scope that includes proper rehearsal are pricing to sustain the professional operation... **Vendors quoting cheaper scope without rehearsal are pricing to sub-professional standard whether they say so or not**」（2026 费率上调六驱动之一=彩排 scope 扩张） |
| Livestorm《Webinar Dry Run: Getting Ready for Your Event》（webinar 平台官方博客·2023-10-24·全文直取 13,041 字符·r468 同源厂）——清单层 | **dry run 定义 verbatim**：「A webinar dry run is **a practice session or a rehearsal for an online event**. It happens beforehand, allowing participants to test the platform, discuss the flow, and plan audience interaction」——三目的=测技术/精炼议程/演练观众互动（投票/Q&A/聊天审核入彩排面）；**副本实例法**：「**Duplicate the webinar**... you can carry over the settings and practice with speakers **without inviting any attendees**」（复制活动实例做彩排场——不占正式位·配置随迁·零观众） | **三段式清单**：Before（彩排场独立排程+全角色邀入〔联席主持/讲者/审核〕+脚本与时间框备妥+连通性预检）/ During（平台控制走查+议程分工面审+互动工具过一遍+品牌背景定制+事故处置预案议）/ After（**录像共享给参与者复盘+问题跟催+活动前一天 check-in〔check in with participants at least one day before〕+开演前 15 分钟进场**〔join the webinar room 15 minutes before the start〕）；连通性测试=平台内置件（彩排即测·问题预曝）；彩排≠策划会：「the practice run **shouldn't be the first planning session**... consider it a dress rehearsal instead of a brainstorming session」 |
| Virtual Velocity《Virtual Event Run of Show: How to Build One That Actually Works》（虚拟活动制作公司 ROS 专文·2026-06-12·全文直取 7,883 字符）——执行层 | **ROS 定义 verbatim**：「A run of show (ROS) is **a minute-by-minute document that maps every element of your virtual event in the sequence it will occur, with exact timing, responsible parties, and technical actions**... **It is not a marketing agenda. It is not a speaker schedule. It is not a slide deck outline**」；**无 ROS 后果 verbatim**：「Without one, even experienced teams end up improvising, and **improvisation in live events rarely looks intentional**」；**contingency 价值句 verbatim**：「Contingencies feel like over-preparation until the moment you need them, at which point they are invaluable」 | **ROS 八列结构**（绝对时间+相对时间双列/段落名/时长/负责人〔主持人/制作 1/制作 2/讲者/技术 lead/Q&A 协调〕/技术动作〔切幻灯片·开录·开 Q&A 面板·开投票窗·转分场·播放赞助视频·静音观众〕/讲者提示语〔绿幕聊天窗给「You're live in 30 seconds」式提示〕/**contingency 注记**/状态列〔未开始/进行中/完成〕）；**五步建法**：营销议程起步→技术段落全入表（暖场页/绿幕检查/开录停录/投票窗/分场转场——观众不可见但制作必需）→讲者转场逐一手接（**干净转场 30-60 秒**）→现实缓冲（**60 分钟活动=55 分钟内容·90 分钟=80-82 分钟**——超时段压缩与剪切预案先定非现场即兴）→高险段 contingency 列（开题主讲缺席=主持延展+制作电话追+最多延 5 分钟；投票工具坏=聊天口头发起跳过结果段；预录视频放不出=口述概括+30 秒排障窗+未解即跳）；**分发与版本控制**：草稿 **≥5 工作日前分发+制作团队评审会**（评审会查冲突比共享文档更有效）+版本号 v1.x+最后更新戳+**末 48 小时锁旧版**（「a misread draft version can cause real problems」）；**ROS=活文档**（演出中制作实时更新打勾·演后注记版=复盘底稿） |

**谱系定谳**：虚拟活动彩排/技术检验结构的行业语法=三层——①**架构层**（四段式 T-minus 时间线·每段单测一面·跳段=质量妥协不是省钱·虚拟比线下更需要彩排〔失败不可当场救〕）；②**清单层**（dry run 三段式 before/during/after+副本实例法〔彩排不占正式位〕+连通性预检+前一天 check-in+开演前 15 分钟进场）；③**执行层**（ROS 八列分钟级脚本+contingency 列+现实缓冲+≥5 工作日分发评审+末 48h 锁版）——与 r482 生产交付周期件（event week=彩排/直播）对位：r482 给「彩排在哪周」·本件给「彩排怎么排+排什么+谁到场」（r502「出了事按什么条款办」+r491「哪些故障算谁的」+r498「奖池折算了没有」+r500「钱按什么钟到账」+r503「排他边界画在哪」同族对仗——本件第八问「**开演前排够了没有**」）。

## §2 城内位的对位定谳：彩排门档期分档行+彩排成本行+彩排沙箱实例行+contingency 彩排段行+升级律行+ROS 交付物行

| 面 | 行业参照 | 城内虚拟活动（超体宇宙城） |
|---|---|---|
| 彩排门（承办前检查单） | 四段式架构+跳段定谳 | **承办前检查单必含彩排门行·档期分档**：全档（大型活动）=四段式全跑〔技术检验 T-7~T-3/全内容干跑 T-3~T-1/带妆终排 T-1/开演前复核 T-90min〕·标准档（常规活动）=技术检验+干跑两段·快闪档（轻量活动）=技术检验单段（当天 tech check 只作复核不作唯一彩排）；**跳段=质量妥协明示**——档期降档是价格决定不是流程省略（档位写进报价单对应行） |

| 彩排沙箱实例 | Livestorm 副本实例法 | **城内对应=彩排沙箱实例**：复制活动实例配置（场景/流道/互动件全随迁）·不进正式活动位·零观众数据残留——**彩排实例数据与正式报名库分立**（r492 数据域同链：彩排试报名/试投票数据不入正式库·活动毕同随原始库返还删除） |
| contingency 彩排段 | 失败模式显式演练+in-the-can | **彩排脚本必含失败模式演练 ≥3 项**（讲者掉线/平台崩溃/幻灯片卡死/音频劣化任选三）+**预录备份素材 in-the-can**（备份段演练部署非仅备着——「requires prior rehearsal to deploy cleanly」）；**只排顺流程不排失败=彩排只做一半**（最被跳过的段=最有价值的段）；大规模档技术检验含**压测窗**（r439 容量件同链：推流分流架构在技术检验段实测非纸面） |
| 升级律 | 小修复测/中备份/大对话 | **彩排暴露临近问题的三档处置**：小=修复+复测/中=备份准备（替补讲者/预录段/形式切换）/大=**减范围或改期对话优于带病开演**（改期走 r490 取消退款件的改期平移通道——「honest conversation about scope reduction or postponement rather than pushing through a broken event」的城内位） |
| ROS 交付物 | 八列+缓冲+锁版 | **ROS=彩排的执行脚本**（彩排按 ROS 行逐行过·干跑计时以 ROS 时长列为标尺）；**ROS 无 contingency 列=禁开演**（高险段无预案=improvisation·直播里的即兴从来不像故意的）；**缓冲律**：60 分钟档=55 分钟内容·90 分钟档=80-82 分钟（超时段压缩剪切预案先定）；**分发与锁版**：ROS 草稿 ≥5 工作日前给客户评审+末 48h 锁版防误读；**ROS 演后注记版入结案数据报告层**（r488 四层谱——实际用时/偏差/触发过的 contingency=复盘与续约证据面·r474 续约同链） |

**消费三句（P3-003 提案窗正文直取）**：
1. **彩排架构句**：承办彩排=四段式 T-minus 时间线（技术检验 T-7~T-3 验技术栈〔基线五项：10 Mbps 上下行/硬线以太网/i5+8GB/有线耳机/备份外设〕·全内容干跑 T-3~T-1 首跑计时·带妆终排 T-1 实况条件·开演前复核 T-90min 验已设好的还在）——虚拟活动比线下更需要彩排（远程讲者断网无人能救·失败不可当场恢复·线上摩擦=观众流失事件），每段单测一面·混段=比只跑一段更差。
2. **彩排成本句**：彩排=真实专业劳动成本行入报价单制作窗显式段（场次/时段/参与面三要素）——报价不含彩排=亚专业标准（客户砍彩排=风险转移书面确认后降档）；承办前检查单含彩排门档期分档行（全档四段式/标准两段/快闪单段·跳段=质量妥协不是省钱）。
3. **contingency 句**：最有价值的彩排段=失败模式显式演练（讲者掉线/平台崩溃/幻灯片/音频 ≥3 项+预录备份素材 in-the-can 演练部署）+彩排沙箱实例与正式活动实例分立（配置随迁·零观众数据残留·试数据不入正式报名库）——只排顺流程不排失败=彩排只做一半；彩排暴露临近大问题=减范围或改期对话（r490 改期平移通道）优于带病开演。

## §3 红线句

**「彩排不是可选项」**——2020 式「开演前一天跟 CEO 测 20 分钟麦克风」时代已终结·跳段=质量妥协不是省钱（r491「SLA 承诺不是垫底托底」同族：质量门的本位律——档期降档是价格决定·流程省略=违约）；配套铁律：**「当天 tech check 替代不了提前彩排」**（同日检查只验证「还在不在」不产生修复跑道——主彩排一周窗：太早=技术记忆不保·太近=发现问题已无窗修）；底线铁律：**「ROS 无 contingency 列禁开演」**（ROS=分钟级八列运营主干非营销议程——高险段无预案=直播里即兴·即兴从来不像故意的；缓冲律同链：60 分钟档只排 55 分钟内容·无缓冲 ROS=注定超时）。
